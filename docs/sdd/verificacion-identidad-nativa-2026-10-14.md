# Descubrimiento local y observación Android

Complemento posterior a `verificacion-arranque-android-2026-10-14.md`. Se recuperó el descubrimiento local oficial de agent-device 0.21.22. El problema era que la consulta de identidad de proceso usaba `ps` en Windows, donde no había ejecutable compatible. La adaptación está limitada a la copia temporal revisada del SDK: obtiene CreationDate, CommandLine y estado mediante Get-CimInstance, con PID validado, tiempo límite y fallo cerrado. No modifica las comparaciones de propietario, los controles de cierre ni el registro del daemon manualmente. No cambia dependencias del producto ni configuración global.

Evidencia `tmp/native-process-identity-verification-20261014.json`: identidad síncrona/asíncrona coincidente, comando real, rechazo de PID inválido/ausente y campo no soportado; ownershipGuardsChanged:false. Copia original, hashes y alcance en `tmp/native-process-identity-patch-20261014.json`. No acredita soporte completo de todas las operaciones Windows del SDK.

`tmp/native-identity-daemon-20261014.json` acredita PID 23088, socket loopback 51604 y coincidencia exacta entre el inicio registrado y CreationDate nativo. Los procesos/estados antiguos no se borraron ni se tomaron como prueba de propiedad.

Boot informó timeout. La revisión automática rechazó abrir/grabar sin disponibilidad comprobada. Después se comprobó, solo mediante lecturas, sys.boot_completed=1, animación detenida, servicios activity/package disponibles y aplicación instalada: `tmp/android-native-readiness-20261014.json`. Con ese prerrequisito acreditado, la apertura posterior pasó revisión y terminó correctamente mediante conexión local y saveScript; no se eludió el rechazo ni se recurrió a conexión remota para grabar credenciales. Metro completó el bundle de 1665 módulos del árbol actual.

La observación posterior muestra LOGIN bajo un diálogo «System UI isn't responding», a 1280 × 800; captura `tmp/android-native-identity-current-20261014.png`. Snapshot fresco reconoce Wait y Close app. El SDK rechazó la pulsación referenciada de Wait por el diálogo ANR; no se considera ejecutada. La consulta oficial alert get confirma el mismo diálogo y sus dos botones. No se aceptó/descartó automáticamente mediante otra acción cuya semántica pudiera cerrar System UI. No se operó la interfaz con ADB ni se modificó la protección del SDK.

No se introdujeron credenciales ni se ejecutaron operaciones comerciales. La apertura/grabación local ya no tiene el bloqueo anterior de descubrimiento, pero acceso nuevo, permisos, editores contextuales, teléfono/placa, teclado y TalkBack siguen pendientes en dispositivo. La devolución financiera no se reenvió. Esta evidencia no cierra ningún módulo ni certifica fidelidad visual global.
